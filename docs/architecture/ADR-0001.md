# ADR-0001 — Pinned platform versions

- **Status:** Accepted
- **Date:** 2026-07-25
- **Milestone:** M0
- **Required by:** §4.1, §4.3, M0 step 2

## Context

§4.3 forbids floating versions (`latest`, `+`) and §4.1 requires a verified NeoForge 21.1.x
patch recorded here with the date it was verified. M0 step 2 explicitly forbids copying a
version number from a tutorial, from an MDK, or from the master build prompt itself.

## Verification performed

Verified on **2026-07-25** against the official NeoForged Maven repository, which is the
authoritative record of what is actually published:

```
https://maven.neoforged.net/releases/net/neoforged/neoforge/maven-metadata.xml
  lastUpdated: 20260724070302
```

- 238 releases exist in the `21.1.x` line.
- The ten most recent are `21.1.232 … 21.1.236, 21.1.238, 21.1.240, 21.1.241, 21.1.242,
  21.1.243`.
- **Latest published 21.1.x: `21.1.243`.**
- Artifact availability was confirmed by HTTP `HEAD` (both return `200`):
  `neoforge-21.1.243-userdev.jar`, `neoforge-21.1.243-installer.jar`.

The `projects.neoforged.net` page named in §4.1 is a client-rendered single-page
application and returns no version data to a non-browser fetch. The Maven metadata it is
generated from was used instead, and is a strictly more authoritative source.

## Why `21.1.235` and not the newest `21.1.243`

Two reasons, both about the machine this actually has to run on rather than about novelty:

1. **Compile against the floor, not the ceiling.** NexusCore declares support for
   `[21.1.235,)`. If it were compiled against `21.1.243` and used any symbol introduced
   after `.235`, it would compile cleanly and then fail at runtime on a `.235` server.
   Compiling against the lowest supported build makes the compiler enforce the support
   range instead of documentation promising it.
2. **It is the deployment target.** The operator's launcher offers `21.1.235` (released
   2026-07-02) as its 1.21.1 NeoForge build. Pinning above what the target server can
   install would make the first release uninstallable on the machine it was written for.

`21.1.235` is also the pairing shipped by the official `MDK-1.21.1-NeoGradle` template,
which is independent corroboration that this Minecraft/NeoForge pair is a valid artifact —
but the pinning decision above rests on the two reasons given, not on the MDK's default.

## Consequences

- Running on a NeoForge build **older** than `21.1.235` is refused by FML at load time,
  which is the intended behaviour.
- Newer `21.1.x` builds are permitted and untested-by-default. Before each release the
  §17.3 matrix is run against the newest `21.1.x` available at that time, and the result is
  recorded in the release notes.
- Re-verify this table at every release. When the pinned NeoForge build moves, update
  `gradle.properties` and append a revision note to this ADR rather than editing history.
