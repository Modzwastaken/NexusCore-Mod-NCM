# ADR-0011 — Release minors carry patch releases; development happens in the minors between

- **Status:** Superseded
- **Date:** 2026-07-26
- **Decided by:** the project owner
- **Amends:** [ADR-0009](ADR-0009.md), [ADR-0010](ADR-0010.md)
- **Restores:** the patch semantics [ADR-0007](ADR-0007.md) originally defined, for release minors
- **Superseded by:** [ADR-0012](ADR-0012.md). The release-line / development-line split is
  withdrawn: every minor behaves the same way. **The empirical finding below survives and is the
  reason `1.0.1` is the hotfix number** — `1.0.0.1` degenerates to `major=0` in Maven, and
  `1.0.0-1` sorts *below* `1.0.0` in Fabric.

## Context

A bug hunt against v1.0.0 found two confirmed critical defects in the **published** release:

- `/teleport` bypasses NexusCore entirely. Vanilla registers `teleport` as the real command and
  `tp` as a *redirect* to it; NexusCore takes over only `tp`, so `/teleport` runs with no
  permission check, no rate limit and **no audit record**.
- Any command source whose entity is not a `ServerPlayer` is granted **root**, so
  `/execute as @e[…] run nexus …` defeats the permission engine and audits as `CONSOLE`.
  Setting `operatorBootstrap=false` — the documented way to stop operators having blanket
  access — does not actually constrain an operator.

ADR-0009 accepted, in writing, that there was no hotfix lane for `1.0.0`, and said: *"If that
changes before `1.5.0`, a lane has to be designed then and this ADR revisited — not improvised
during an incident."* This is that moment.

## What was measured, not assumed

A hotfix needs a version string that **all three loaders parse correctly and order above
`1.0.0`**. Four candidates were tested against the actual parsers — Fabric Loader 0.19.3's
`VersionParser`, and `maven-artifact` 3.8.5's `DefaultArtifactVersion`, which is what NeoForge
and Forge use:

| Candidate | Maven (NeoForge / Forge) | Fabric | Usable |
|---|---|---|---|
| `1.0.1` | `major=1`, orders `+1` | orders `+1` | **yes** |
| `1.0.0.1` | **`major=0`** — the whole string becomes a *qualifier*; Maven supports three numeric components plus a hyphenated build number, not four | orders `+1` | no |
| `1.0.0-1` | `major=1`, orders `+1` | **orders `−1`** — semver reads `-1` as a pre-release identifier, sorting it *below* the release it fixes | no |
| `1.0.0.hotfix1` | `major=1`, orders `+2` | orders `+8` | works, but the ordering distance is an artefact of string comparison rather than anything meaningful |

**`1.0.1` is the only candidate that is correct in both.** The four-component form proposed
when this lane was first discussed does not survive contact with Maven, and the hyphenated form
sorts backwards in Fabric — which is the worst possible failure, because a loader would treat
the hotfix as older than the version it fixes.

## Decision

**A minor is either a release line or a development line, and the third component means
different things in each.**

| Minor | Kind | Third component |
|---|---|---|
| `y ∈ {0, 5}` — `1.0.x`, `1.5.x`, `2.0.x` | **Release line** | `x.y.0` is the feature release. `x.y.1`, `x.y.2`, … are **published patch releases: fixes only, no new features, no data-format change.** |
| `y ∉ {0, 5}` — `1.1.x` … `1.4.x` | **Development line** | `x.y.1`–`x.y.4` are internal development builds; `x.y.5` is the pre-release; then the minor rolls. |

So the road from `1.0.0` to `1.5.0` is **four development lines of five**:

```
1.0.0  release ──► 1.0.1, 1.0.2, …   published patch releases (fixes only)
  1.1.1 … 1.1.4  development     1.1.5  PRE-RELEASE
  1.2.1 … 1.2.4  development     1.2.5  PRE-RELEASE
  1.3.1 … 1.3.4  development     1.3.5  PRE-RELEASE
  1.4.1 … 1.4.4  development     1.4.5  PRE-RELEASE
1.5.0  release ──► 1.5.1, 1.5.2, …   published patch releases
```

Twenty development rungs and four pre-releases. After `1.5.0`, the ladder to `2.0.0` runs
`1.6.x` … `1.9.x` by the same rule.

## Why this is better than the lane it replaces

ADR-0009 reinterpreted the third component as a build counter *everywhere*, which is what
removed the ability to patch a shipped release. This confines that reinterpretation to
development minors and **restores ADR-0007's original patch semantics where a patch actually
makes sense** — on a line that has been released.

It also resolves ADR-0009's stated cost #1. `1.0.1` now means exactly what a semver reader
expects: a fixes-only patch of `1.0.0`. The versions that do *not* mean what semver expects are
confined to minors that are never published.

## What this costs

1. **The development work already numbered `1.0.1` has to be renumbered to `1.1.1`.** Nothing
   had been committed, published or handed to anyone, so this is a rename rather than a
   rewrite of history. It would not have been, a week later.

2. **The ladder loses a line** — five lines of five becomes four of five, twenty rungs instead
   of twenty-five, because `1.0.x` is no longer available for development. The 1.0.x line's
   work is redistributed rather than dropped; `IMPLEMENTATION_STATUS.md` shows where each item
   went.

3. **Two version shapes now coexist and look identical.** `1.0.2` is a published patch release
   and `1.2.2` is an internal development build, and nothing about the strings says so. The
   minor is the discriminator, which is learnable but not self-evident. `versionLadderCheck`
   rejects the wrong changelog label for each, which is the only enforcement available.

## Enforcement

`versionLadderCheck` gains the release-line/development-line distinction. On a release minor it
requires a patch-release heading and **forbids** the `development build` and `pre-release`
labels; on a development minor it enforces ADR-0010's rules unchanged. Every rule is proven to
fail as well as to pass.

## Consequences

- A patch release runs the full `RELEASE_CHECKLIST.md`: it is published, so it is a release.
  Its scope is narrower, but the ceremony is not reduced.
- `1.0.1` is the hotfix for the two critical defects above, and contains **nothing else** — no
  ladder work travels with it. That is the entire point of having the lane.
- ADR-0009's "there is no hotfix lane" consequence is withdrawn.
- ADR-0010's five-rung line, `.5` pre-release, and minor-roll rules are unchanged for
  development minors.
